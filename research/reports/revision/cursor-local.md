# Cursor local telemetry: feasible without Enterprise, but preserve source semantics

Date: 2026-09-30. Scope: published code, synthetic fixtures, official docs/support, primary reverse-engineering observations. No personal databases inspected. Verdict: **SUPPORTED** that local non-Enterprise capture can deliver conversations, tool/edit evidence, timing where present, workspace links, and Cursor's own commit attribution. **CONTESTED** that it reliably delivers cumulative billed tokens/cost or exact human rewrite attribution.

## Decision

Build separate opt-in adapters for (1) hook-referenced transcripts, (2) global/workspace SQLite snapshots, (3) AI tracking DB metadata, (4) user-selected Markdown exports, and (5) opportunistic usage fields. Keep live hooks as the event-time/repo/branch anchor. Local historical import supplies rich evidence; it must never silently inherit today's branch. Ratstack does not change these storage facts. Prior blanket statements that local Cursor has "no tokens" are too strong: fields exist, can be zero, and context meters exist with different semantics.

## JSON structures worth decoding

1. `cursorDiskKV['composerData:<composerId>']`: `fullConversationHeadersOnly` gives ordered bubble references; older `conversationMap` embeds content. Metadata includes `createdAt`, mode and model configuration. `bubbleId:<composerId>:<bubbleId>` carries `text`, `type`, `createdAt`, `requestId`, `modelInfo.modelName`, `codeBlocks`, and often `tokenCount.inputTokens/outputTokens`. Use the composer in the key when JSON `conversationId` is blank. Deduplicate physical revisions and shared request IDs; a SQL row is not automatically a visible message or model call. [Pinned parser](https://github.com/getagentseal/codeburn/blob/986d72ce1efbfaf40b3c9d4050d9ecdbc24be986/src/providers/cursor.ts)

2. `agentKv:blob:<hash>` JSON variants: `role`, `content`, `providerOptions.cursor.requestId`, `providerOptions.cursor.modelName`; content can contain structured tool calls/results. Request ID joins bubble records. Binary/non-JSON variants need a separate decoder; silently dropping them is a coverage gap. Use structured calls for commands/file paths; strings alone do not establish execution success. [Pinned codeburn parser](https://github.com/getagentseal/codeburn/blob/986d72ce1efbfaf40b3c9d4050d9ecdbc24be986/src/providers/cursor.ts)

3. `checkpointId:<composerId>:<checkpointId>` carries file URI and `originalModelDiffWrtV0` ranges/modified lines; bubble `checkpointId` joins. `messageRequestContext:<composerId>:<messageId>` can carry files, diffs and terminal context. Both can contain full private source; ingest metadata/diff counts first. These prove a stored snapshot/context, not that all suggested edits were accepted. [Storage reverse-engineering](https://github.com/Callum-Ward/cursaves/blob/2919739d35a043f1f35979a758f87d4c936a42b7/docs/how-cursor-stores-chats.md)

4. Index drift: read older workspace `composer.composerData.allComposers`, workspace `composer.composerHeaders` where present, global `ItemTable['composer.composerHeaders'].allComposers[].workspaceIdentifier`, and feature-detect the separate `composerHeaders` table. A global index may miss un-reopened migrated chats. Do not infer workspace hashes from paths. [Migration evidence](https://github.com/Callum-Ward/cursaves/blob/2919739d35a043f1f35979a758f87d4c936a42b7/docs/how-cursor-stores-chats.md), [new table synthetic fixture](https://github.com/tony/agentgrep/blob/14985d5e27450a547726b1042e909c6412d7603d/tests/samples/cursor-ide/cursor-ide.state_vscdb/composer-headers.sql)

## Tokens, timing and honesty

- **Stored numeric fields are not guaranteed billed usage.** Older nonzero bubble token counts are useful observed usage; zero values on current builds can be placeholders, not proof of free/no work. `composerData.promptTokenBreakdown.totalUsedTokens` and `contextTokensUsed` are latest context-window meters; never sum as per-turn usage or relabel as total feature tokens. Codeburn's synthetic tests cover precedence and avoiding duplicate conversation-meter credit; its parser comments explicitly distinguish meter from cumulative usage. [Token tests](https://github.com/getagentseal/codeburn/blob/986d72ce1efbfaf40b3c9d4050d9ecdbc24be986/tests/providers/cursor-real-tokens.test.ts)
- **Visible text estimates are a separate metric.** Character/token heuristics omit context resend, cache, hidden reasoning and discarded generations. Even a model tokenizer can only count visible content. Never turn a guessed `auto` model into exact dollars. Codeburn documentation's char-estimate behavior and pricing assumptions are inspiration to challenge, not evidence of bill parity. [Provider limitations](https://github.com/getagentseal/codeburn/blob/986d72ce1efbfaf40b3c9d4050d9ecdbc24be986/docs/providers/cursor.md)
- **Opportunistically retain optional hook usage fields** if an installed build emits them, with exact adapter/version provenance; do not predeclare absent because docs omit them. Root's other research lanes found optional stop-hook input/output/cache fields in upstream collectors. Their per-turn versus cumulative semantics still require fixtures and a controlled live compatibility probe; until verified, expose raw counters separately rather than sum. This report did not independently validate those hook implementations.
- Bubble `createdAt` can be wall-clock ISO; composer timestamps are often epoch milliseconds. Primary observed data also records sparse `timingInfo.clientRpcSendTime/clientSettleTime/clientEndTime` wall-clock values while `clientStartTime` can be monotonic uptime. Compute duration only between compatible clocks with a valid pair. JSONL file mtime cannot assign exact times to each turn. [Primary observed schema/timing research](https://github.com/alp82/aistack/blob/main/docs/research/harness-adapters-2026-08.md)
- CLI `store.db` tests cover content-addressed JSON message blobs and protobuf roots: message IDs in field 1, workspace URI in field 9, epoch-ms stamp in field 26. Prompt `<timestamp>` strings give minute-resolution fallback, not precise tool spans. Retain origin/granularity. [CLI synthetic tests](https://github.com/getagentseal/codeburn/blob/986d72ce1efbfaf40b3c9d4050d9ecdbc24be986/tests/providers/cursor-agent.test.ts)

## AI tracking columns and Git correlation

Published version observations enumerate:

- `ai_code_hashes`: `hash, source, fileExtension, fileName, requestId, conversationId, timestamp, model, createdAt`.
- `scored_commits`: `commitHash, branchName, scoredAt, linesAdded, linesDeleted, tabLinesAdded, tabLinesDeleted, composerLinesAdded, composerLinesDeleted, humanLinesAdded, humanLinesDeleted, blankLinesAdded, blankLinesDeleted, commitMessage, commitDate, v1AiPercentage, v2AiPercentage`.
- `conversation_summaries`: conversation ID, title/TLDR/overview/bullets, model, mode, update time. It can be empty.
- `tracked_file_content`: path/content/conversation/model/extension/time; `ai_deleted_files`: path/composer/conversation/model/deletion time.

[Agentgrep version observation](https://github.com/tony/agentgrep/blob/14985d5e27450a547726b1042e909c6412d7603d/docs/_observations/cursor-cli/2026.09.10-fd3934a.toml) is a primary catalog, not Cursor's documented contract. Verify SQLite column presence rather than assuming all schemas. Join `scored_commits.commitHash` to the actual repo commit, then branchName as a corroborating string; branches are reused/deleted/renamed. Join hash rows via request/conversation plus normalized file paths to observed workspace/repo. Existing scores measure Cursor-attributed contribution at commit time; they do not establish survival through review or human rewrite causality. Unknown/default model is genuinely unknown. Commit-level numbers must display scored/total-commit coverage and missing denominators.

**Recommendation (inference):** maintain event-time repo-root, worktree, branch, HEAD SHA and flight ID in the local recorder. Historical workspace→repo mapping can be exact; historical branch association is reconstructed unless a stored commit/branch or explicit flight mapping exists. Multi-root and SSH need URI-aware roots, not basename matching.

## Correct read-only live snapshots

Use SQLite's read-only URI connection and backup API into an operation-owned scratch file; parse the snapshot. SQLite's [Online Backup API](https://www.sqlite.org/backup.html) provides a consistent snapshot of a live source. [WAL docs](https://www.sqlite.org/wal.html) explain that read-only WAL needs accessible sidecar state or suitable immutable conditions. Read-only may fail when required sidecars cannot be used; report unavailable/retry rather than mutate/checkpoint the source.

Do **not** independently copy a live DB then its `-wal/-shm` and claim atomic consistency. Do **not** use `immutable=1` on a changing live DB to evade locking: [SQLite URI docs](https://www.sqlite.org/uri.html) say immutable asserts it cannot change and disables locking/change detection; a false assertion risks wrong query results/corruption errors. An immutable URI is appropriate only for a stable complete snapshot. Do not vacuum, delete records, reset journals, or import into Cursor. Global and workspace DB snapshots are not jointly atomic; include snapshot times and mark ambiguous/missing mappings. Cache fingerprints must include WAL changes/source observation, not only main DB mtime/size.

## Independent implementation lanes / pass conditions

1. Snapshot adapter: synthetic WAL-writer fixture; show newly committed WAL rows, no source mutation, bounded retries, owner cleanup, malformed JSON isolation.
2. Bubble/index adapter: mixed legacy/current schema fixtures, ordered visible bubbles, orphan/subagent/duplicate handling, partial counts.
3. Transcript adapter: TXT/JSONL/child files, incomplete last line, disabled route, timestamps absent, exact session ID; cross-route dedup.
4. Attribution adapter: all optional tables/columns, empty data, full SHA join, repeated branch names, unknown models, no full-content ingestion default.
5. CLI store adapter: opt-in versioned protobuf/JSON decoding; test legacy and lowercase new-root paths independently.
6. Report evidence contract: every value carries source/classification/coverage; context meter and text estimate cannot masquerade as billed tokens; no timestamp/branch synthesis hidden from user.

Critical-path recommendation: hooks + one local transcript parser + Git/GitHub should produce the live flight. DB, checkpoint, tracking and CLI probes can proceed in parallel behind that stable envelope and contribute whatever capabilities genuinely pass; failures reduce coverage, not block the demo. This is a prioritization recommendation, not a duration estimate.
