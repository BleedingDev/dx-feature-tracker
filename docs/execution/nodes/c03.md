# C03 identity audit: handoff

Status: **ready**. Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.

Owned file: `packages/core/test/dx/audits/c03.test.ts`. It runs the real B02 collector against scoped temp Git repos, then feeds the events through the B23 repo map and the B24 flight correlator. No user repositories are read.

## Verified (8 tests)
- **Linked worktrees:** they share `repoCommonDir` but keep separate worktree paths, branches and flights. An edited file maps to its own worktree. A path set spanning two worktrees is not assigned. Removing one worktree leaves the other intact.
- **Branch reuse:** delete and recreate gives a new `branchCreatedAt` and a second implicit flight.
- **Rename:** the creation time and head survive. Implicit flights split on a rename; `marker.start` plus `alias:<new>` keeps one strong flight.
- **Rebase:** head and base SHA move, creation time stays the same, and the implicit flight stays the same.
- **Forks/clones:** the same branch and head still give separate repos, events and flights, and fork paths do not resolve against the upstream map.
- **Detached HEAD:** branch is null, coverage is partial, and the flight is `unassigned` (primary checkout and linked worktree). B23 reports `detached`.
- **Unborn HEAD:** the collect succeeds, the branch is kept, `headSha` is null and there is an `unavailable:headSha` gap.

## Findings
1. **(medium, B02)** The `git.context` upstreamKey leaves out `branchCreatedAt`. A branch recreated at the same HEAD gets the **same eventId**, so the store dedupes it and the reused branch never becomes a new flight. The test asserts the current collision; flip it when fixed.
2. **(low, B24/A02)** A plain rename with no alias splits into two provisional flights, even though `branchCreatedAt` is equal.
