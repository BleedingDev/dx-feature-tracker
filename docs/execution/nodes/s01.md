# S01 storage handoff

S01 is complete. All twenty-one storage tests pass, including consumed terminal recovery across ordinary reset/restore, measured reads, bounded pages, cursor CAS and replacement proofs. Scoped lint, formatting and focused independent reviews are clean. The earlier schema 7 nineteen-case checkpoint is preserved in the JSON receipt. Final packaged acceptance remains with root Build7 and its workspace fence. The implementation uses Node 24.18.0, Effect 4.0.0-rc.117 and store schema 8.

`SqliteAgentStoreLayer(options)` provides `EventStore | AgentStore | HarnessCursors | BoundedEventReplacement` from one existing `DatabaseSync` connection. `openSqliteEventStore(options)` returns the legacy `service`, `agentService`, `cursorService`, `appendBounded`, and `close`. Legacy EventStore signatures and mocks are unchanged. AgentStore mutations use serialized SQLite transactions; scoped reads use a consistent read transaction. Owner close is one atomic metadata update.

```text
one opened SQLite writer
  -> legacy source events and snapshots
  -> captured selection + full immutable basis
  -> metadata header + indexed result items and series
  -> operation reservation + receipt CAS + step journal
  -> authored learning revisions + independent evaluations
  -> harness cursor CAS + bounded replacement proof

writer reopen
  -> persisted owner nonce + PID + process start
  -> known live owner: preserve running receipt
  -> closed or absent owner: interrupt unfinished steps
  -> preserve committed steps, counts and safe cursors
```

Source capture binds the raw selected events, half-open window, scope, watermark and exact current coverage atomically. Basis records retain interpretation inputs and captured price sheets. Warm pages read capped metadata and bounded indexed rows instead of decoding the full historical basis or projection. Item and series cursors can select their own lane. Current coverage uses its latest-row index and observed event placements. Unresolved branch selection retains recorded source gaps and explicitly discloses unknown placement; unavailable tool/worktree placement also has an explicit gap.

`readBasisMetadata(handle, cap)`, `readLatestBasisMetadataForScope(scope, cap)`, `readResultMetadata(handle, cap)` and `readMatchingResultMetadata(basis, capability, digest, cap)` report actual stored header bytes and examined header rows. Latest and matching reads use indexed selections. A matching header refused by the byte cap returns `metadata: null`, zero decoded bytes and one examined row; a missing header returns zero for both counters. Legacy getters retain their typed failures. Padded fixtures measured 2,492 basis header bytes versus 1,787 after normalization, and 974 result header bytes versus 614. Oversized malformed headers were refused before parsing.

`readCursor(handle, cap)` gates persisted cursor bytes before materialization, then checks identity, generation, epoch, basis/result binding, digest, projection version, axis and positions through indexed scalar fields. It does not decode analysis headers. The fixture measured 628 stored cursor bytes versus 325 after normalization, with one examined row; cap refusal decoded zero bytes. `readResultPage` includes one mandatory header fact and gates the combined summary, disclosures and resolution bytes in SQL before returning their JSON fields. A one-fact budget preserves both page positions. Independent read-only reviews confirmed these guards.

Harness cursor updates use `putIfCurrent(ref, expected, next)` to compare the complete stored cursor inside one SQLite write transaction. Equal file timestamps and sizes do not authorize overwriting a changed token offset. The cursor service closes with the store connection, and its memory implementation uses atomic `Ref.modify`.

`appendBounded(batch, {maxRemovedRecords, maxRemovedBytes, maxElapsedMs})` inspects old rows through an adapter/time range index with a row limit. It proves stored byte lengths before decoding bodies, then replaces inside the same transaction. Record or byte refusal leaves events, coverage and retained results unchanged. The returned proof has exact removal count, body digest, decoded bytes and up to 500 event IDs with an explicit omission count. Digests follow timestamp order with a sequence tie-break. A partial batch without an explicit replacement selector preserves prior rows. Elapsed overruns roll back before commit.

Operation reservations bind the exact plan, digest and idempotency key before mutable authority checks. Revision and writer ownership protect receipt updates. Cancellation preserves the original execution owner. A reopened store interrupts a running receipt only when its persisted owner is closed, absent, or demonstrably replaced by another process using the same PID. Unknown ownership stays running. Reset and restore invalidate mutable plans and continuations, while exact consumed reservations and preserved receipts recover through safe generation aliases.

Ordinary reset and restore also recover completed consumed receipts without replay. The original terminal state, revision, timestamps, steps and effects remain unchanged; only the receipt's top-level store handle and ownership metadata change. Exact reservation binding is checked before recovery-only promotion. Failed receipts stay terminal, and invalidated reservations cannot turn unused plans into authority. Existing aliases point directly to the current receipt after each move, so repeated resets do not exhaust the sixteen-hop lookup guard. The fixture verified succeeded export and failed-with-no-effects receipts through eighteen actual source-deleting resets and restore.

Migration 8 adds only `agent_operation_aliases_operation` on `agent_operation_aliases(operation_id)`. It rewrites no event bodies, interpretation inputs, policy or semantic contract versions. A controlled v7-to-v8 reopen preserved store identity, a v1 basis, its result and original reservation. Invalidation checks stored receipt byte lengths before materialization and checks encoded replacement bytes before writing. It streams per-record bodies under the operation byte cap; total metadata work still grows with retained operations and aliases. Alias history preserves origin metadata for recovery, not deleted source bodies.

`getOperationPlanForReceipt(operation)` recovers the original reviewed plan through the validated receipt and original reservation. It preserves immutable scope, arguments, effects, expiry and digest; stale or expired validity is presentation only. Normal plan lookup, reservation and apply authority remain unchanged. A missing retained plan returns null without changing the receipt or store identity.

Admin code calls `invalidateAgentState(db, reason, {preserveOperationId?})` inside its existing transaction. Preserve `AGENT_RECOVERY_TABLES` during restore copying; it includes operation plans, receipts, step journals, reservations, aliases and writer owners. Source privacy deletion calls `tombstoneAgentScope`; adapter replacement calls `tombstoneReplacedAgentEvents`. Authored learning survives source deletion and its citations become unavailable rather than redirecting to replacement observations.

Learning records retain revision history and enforce revision CAS. Evaluation append does not mutate the parent revision, so concurrent evaluations both survive. Exact evaluation lookup supports durable retries without scanning the history. Reference resolution checks store identity, generation, scope and optional historical learning revision. Unsupported unindexed reference kinds return explicit reasons.

Projection retention defaults to 32 MiB, counting the stored projection, indexed rows and page header payloads. The oldest retained projections are evicted first; stable metadata survives and content reads return `basis-content-unavailable`. Basis, learning and operation records have explicit byte limits. Authored learning, evaluation and operation history has no implicit eviction. Source selection captures retain at most 1,024 records.

The named `s01-isolated-agent-storage` fixture measured an item page at three examined facts and 311 decoded bytes, and a series page at two facts and 308 bytes. Each includes its mandatory header. Peak retained projection data was 616 bytes under an 800-byte fixture cap. The replacement proof examined two removed rows and decoded 1,530 bytes. All observations were labelled fixtures in isolated stores. No live source acquisition, network request, dependency install or build tree was created.
