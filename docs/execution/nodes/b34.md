## Metrics (per snapshot, so per branch when the selector is a branch)

| id | value |
|---|---|
| `dx.friction.test-runs` | number of `test.result` events |
| `dx.friction.test-failures` | failed runs: failed+errors > 0, status or outcome failed |
| `dx.friction.test-failure-rate` | failed runs / runs with a known outcome |
| `dx.friction.tool-call-failure-rate` | failed hook tool calls (`postToolUseFailure` or a failed status) / hook tool calls |
| `dx.friction.failed-commands` | `command.run` with exitCode != 0 or a spawnError (denominator = command runs) |
| `dx.friction.reworked-files` | files with at least 5 agent edits (`ai.tool-edit`) / files the agent edited |

All results use method `observed`. When there is no evidence, the value is null with state `unavailable` and a reason (never 0). A result is `partial` when outcomes are unknown or coverage is incomplete. If more than one adapter reports tests, the result is `partial` with attribution `provisional`, because the same run may be counted twice.

## Findings (ranked by severity, then weight, then id; at most 10)

| id | threshold | severity |
|---|---|---|
| test-repeated-failure:<test> | same test failing in at least 2 runs | high |
| test-failure-rate | at least 3 known runs and a rate of 50% or more | medium |
| tool-failure-rate | at least 3 failures and a rate of 20% or more | medium |
| command-repeated-failure:<cmd> | same command failing at least 2 times | medium |
| file-rework:<file> | at least 5 agent edits | low (medium at 10 or more) |

Each finding cites evidence IDs and suggests an experiment someone can inspect. Findings never estimate time or money saved. The test checks for this.

## Gaps

- The integration owner has to register `frictionMetric`. B34 does not edit barrels or registries.
- Duplicate test runs across adapters are only flagged, not joined.
- Rework is measured only as agent edit events per file. Line churn and human rewrites are not observed here.
