## Behaviour
- analyze: it uses `selectAnalyzeSnapshot` (B35). Pinned `snapshotId` reuses the stored snapshot, and an unknown or expired ID fails with `SnapshotNotFound`, with no substitution. Latest and asOf snapshots get `enabledDescriptors` (ready/degraded only) and `metricDefinitions` stamped into the manifest, which is then persisted with `putSnapshotManifest`. Metrics are computed, and a throwing metric becomes a note instead of a crash. The report is composed with the disclosures (latest ID, changed-evidence watermark note, "Persisted snapshot metadata <id>", metric definition drift on pinned). The returned `report.snapshot.snapshotId` is reusable by explain and evidence.
- explain/evidence: B36/B37 functions with the same selection rules. The evidence excerpt is redacted: the fixture prompt text is asserted absent.
- Validation (`InvalidInput`): the call is rejected for blank or oversized text, non-ISO `asOf`, `snapshotId` combined with `asOf`, or empty or >100 `evidenceIds`.
