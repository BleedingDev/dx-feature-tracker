# B44 handoff: Cursor SDK collector (optional). Status: DISABLED, tested on fixtures plus a real SDK record

Status: **disabled**. The code works, and its tests pass on fixtures plus one real `@cursor/sdk@1.0.34` run record. It stays disabled because the host has no `CURSOR_API_KEY`. The SDK rejects the cursor-agent login with `Invalid User API Key`. Because of that, no real run that reports tokens or cost could be produced.

## What it does
- `cursorSdkCollector` / `cursorSdkDescriptor` (`collector/cursor-sdk`) live in `packages/core/src/dx/collectors/cursor-sdk/collector.ts`. The line parser is in `parse.ts`. It needs `FileSystem`. The pure entry point is `parseCursorSdkFlightRecord(text, {ref}, input, observedAt)`.
- It reads only an explicitly selected JSONL flight record (`--input`). The caller's own SDK instrumentation writes that file. The collector never runs the SDK and never calls Cursor APIs.
- Line format `dxfr.cursor-sdk.v1`: `{schema, record: "stream"|"result"|"settlement", recordedAt, flight: {branch, flightId?}, ...}`.
  - `stream` + `message` (an SDKMessage): only `usage` and `tool_call` messages are used. Tool args and results are never read. Text, thinking and user messages are dropped.
  - `result` + `agentId` + `result` (the `Run.wait()` RunResult).
  - `settlement` + `agentId` + `usage` (the `agent.getUsage()` AgentUsage).
- Records without an explicit `flight.branch` tag are rejected with a `missing-flight-tag` gap. If a selected context branch is set, records tagged with another branch are skipped with a `flight-tag-other-branch` gap.
- No double counting. For each agent:
  - If a settlement exists (latest snapshot in the file), its per-run rows are the `ai.usage` events that carry `tokens` and `charge` (chargedCents/100, source-reported). The run result is then `ai.request`, and its `runTokens` are informational only.
  - If there is no settlement, a run result that has usage becomes `ai.usage` with `charge: null` and a `cost-unsettled` gap.
  - Streamed per-turn usage becomes `ai.turn` with `liveTurnTokens` and is not counted.
  - When the agent total is larger than the sum of its runs, the difference goes to a `provider-bucket` aggregate event.
- `reasoning` is kept as its own category. It is a subset of output, so the SDK `totalTokens` value is stored raw only. `rawCostCents` becomes `rawCostUsd` and is not treated as a charge. `durationMs` becomes `agentDurationMs`, which is agent time, not human waiting.
- Tool calls: one `ai.turn` event per `call_id`, carrying `toolCall: true`, `toolName`, and `status` set to ok, failed or running. The friction metric picks these up.

## Fixtures
- `b44-cursor-sdk-flight-record` (`fixtures/b44/flight-record.jsonl`) is synthetic. It covers a settled agent with a remainder, an unsettled errored run, tool calls, content that must not leak, an untagged line, a wrong schema, bad JSON and another branch.
- `fixtures/b44/live-sdk-1.0.34-unauthenticated-run.jsonl` is real SDK output from a scratch repo on branch `feat/sdk-live`, model `composer-2.5`. The run ended with status error and no usage. The collector turns it into a single `ai.request` event and zero usage rows.

## Re-enable path
1. The user sets `CURSOR_API_KEY`.
2. Wrap the SDK: call `Agent.create({local:{cwd}, model:{id}})`, then `send`. For each streamed usage or tool_call message, append a `stream` line. After `wait()`, append a `result` line. After a short delay, append a `settlement` line from `getUsage()`. Every line is tagged with the branch.
3. Import the file with `--input`.
4. Flip `readiness` to `degraded`. A02/A07 then register the module.

No new dependency is needed in the repo. The wrapper lives in the user's own script.
