# B45 handoff: git-ai collector (optional) — DISABLED, fixture-tested

Status: **disabled**. The code works and passes its tests on fixtures. It is disabled because git-ai is not installed on this host (`which git-ai` exit 1, `git ai` is not a git command, no `~/.git-ai`). So no real input has been shown to work.

## What it does
- `gitAiCollector` / `gitAiDescriptor` live in `packages/core/src/dx/collectors/git-ai/collector.ts`. The parsers are in `parse.ts`. The collector needs `FileSystem | Path`; provide `NodeServices.layer`.
- It reads only an explicitly selected `--input`: a directory, or a single file, with `<sha>.note` files (`git notes --ref=ai show <sha>`) and/or `<sha>.stats.json` files (`git-ai stats <sha> --json`). It never runs git-ai, never initializes it, and never reads, fetches or pushes notes refs.
- It emits `provenance.attestation` events keyed `authorship-note:<sha>` / `stats:<sha>`, with `identity.commitSha` set and `occurredAt` null.
- Notes: only `authorship/3.x` is accepted. Anything else gets an `unsupported-schema-version` gap. The parser sums attested line ranges per file and keeps per-prompt counters, tool and model. Prompt messages and `human_author` are dropped. `unattestedAdditions` is null because a note does not contain the diff totals.
- Stats: the parser keeps the source counters. `unattributedAdditions` = added − ai − human − mixed, but only when those categories reconcile. Otherwise it is null with a reason. `aiAdditionShareAtCommit` is labelled as commit-time only. `retention` is always null.
