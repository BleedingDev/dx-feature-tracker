# B04 git observation handoff

Status: **ready** (optional node). Contract `dx.contracts.v1`, digest `sha256:b9623bd4...b090`.

## What it does
Opt-in collector `gitObservationCollector` (adapterId `git-observation`, descriptor `collector.git-observation`). Given an explicit worktree path (`selectedInput`), it runs read-only git (`GIT_OPTIONAL_LOCKS=0`) and emits `git.observation` events:

- `working-tree`: branch, head, upstream, ahead/behind, tracked/staged/untracked/conflicted counts, uncommitted lines added/deleted, binary count, content fingerprint (hash-object without -w). Event ID keyed on the state hash, so repeat collects of an unchanged tree dedupe and each distinct edit state is a new event with its first-seen time.
- `branch-reflog`: one event per branch reflog entry with action only (`commit`, `commit (amend)`, `reset`, `branch`...), `createdFrom`, time. Commit messages are dropped.

Coverage is always `partial`, with gaps listed. It does not claim complete history.
