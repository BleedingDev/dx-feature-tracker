# B09 cursor-extension collector: disabled (tested)

- **Status:** disabled. The parser and collector have tests, but no producer runs on this host. Do not register it as ready.
- **Feasibility:** the supported route is a VS Code/Cursor extension that the user installs. It would use only the public API: window focus, document save, active editor changes, and branch/HEAD from the git extension. It would append `dx.cursor-extension.activity.v1` JSONL. That gives editor activity per branch only. The public extension API exposes no Cursor AI tokens, cost, requests or tool calls, so this route can never supply them.
- **Probe:** Cursor IDE 3.22.12 is present (source-probes.json). No recorder extension exists or is installed.
- **Exports:** `packages/core/src/dx/collectors/cursor-extension/collector.ts` exports `cursorExtensionDescriptor`, `cursorExtensionCollector` (`DxCollector<FileSystem.FileSystem>`), the pure `parseCursorExtensionActivity` and the record schema.
- **Behaviour:** it reads only the explicitly selected `--input` file. A null input gives `InvalidInput`; an unreadable input gives `SourceUnavailable`. Records that fail to parse are counted in the `rejected-records` gap. Unknown fields are dropped, and a secret canary test covers this. Event IDs come from sha256(adapterId, upstreamKey `sessionId:seq`, kind), so duplicates collapse. The cursor is a line index. Coverage is `partial` with three permanent gaps.
- **Fixture:** `b09-cursor-extension-activity` (`packages/core/test/dx/fixtures/b09/activity.jsonl`). It is synthetic and redacted, and it is not added to the fixture index (A04 owns that index).
- **Checks:** `pnpm --filter @rat-stack/core exec vitest run test/dx/b09.test.ts` exits 0 with 6 passed. oxlint and oxfmt --check pass on the B09 files (exit 0). Core tsc reports 0 errors in B09 files (its overall exit is nonzero because of other owners' files).
- **Contract note:** v1 has no IDE-activity event kind, so events use `kind: "other"` with `payload.category: "ide.activity"`.
