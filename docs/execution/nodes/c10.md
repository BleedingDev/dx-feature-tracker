## Result

The audit ran the Cursor hook path (handler, then spool, then decode, then events and stdout), the Cursor transcript parse, and B37 evidence export against injected prompts, tokens, shell and MCP instructions, edit content and output. None of that content reaches stored or exported data.

The test proves nothing is executed with a sentinel file that is never created and a git resolver whose calls are counted. Module mocking is banned by lint, so the test uses dependency injection instead.

## Known findings, to route to their owners

1. **B05, high.** In `cursor-hooks/sanitize.ts`, `firstToken` stores `GITHUB_TOKEN=<secret>` as `commandBin` in the spool and in the event payload.
2. **B37, medium.** In `redact.ts`, the credential-pair regex misses compound labels such as `AWS_SECRET_ACCESS_KEY=` and `GITHUB_TOKEN=`.
3. **B37, low.** A bare, unlabelled AWS secret passes. This gap was already disclosed.

Once an owner fixes one of these, its `it.fails` test fails. At that point change it to `it`.
