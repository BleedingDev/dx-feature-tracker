# B24 flight correlation: handoff

Status: **ready**. Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.

## What exists (`packages/core/src/dx/correlation/flight/`)
- `deriveFlightId(parts)`: deterministic UUID (v5-shaped, sha256 of `dx.flight.v1` + parts). Explicit flights: `["explicit", repoCommonDir, startEventId]`; implicit: `["implicit", repo, branch, firstEventId]`. A `marker.start` may carry its own ID in `context.flightId` or `payload.flightId` (UUID); it is kept verbatim.
- `buildFlightRegistry(events, mappings)`: order-independent.
  - `marker.start` freezes start time, base SHA (`payload.baseSha` ?? `context.headSha`), label and branch alias. A second start for the same ID is ignored with reason "frozen".
  - `marker.stop` closes by flight ID, else the single open explicit flight on that branch/repo; ambiguous or duplicate stops are ignored with a reason.
  - Mapping `{ key: "alias:<branch>", value: <flightId> }` adds a branch alias (rename).
  - Events on a branch outside every explicit window form implicit, provisional flights per (repo, branch) segment. A new segment starts after an explicit flight, or when `payload.branchCreatedAt` changes (branch deleted and recreated). This is how branch reuse gets a new ID.
- `flightCorrelator: DxCorrelator` / `correlateFlights`: one `Correlation` per event, `targetKind: "flight"`:
  - `strong`: explicit flight ID on the event, a marker, or exactly one explicit window covering the branch and time.
  - `provisional`: implicit branch flight; unknown pinned flight ID (target null); untimed event whose alias has exactly one flight.
  - `unassigned`: detached HEAD (`HEAD`, empty branch, or `payload.detached`), overlapping windows (multi-root without repo context), untimed reused aliases, and ignored markers.
  - Earlier events never inherit a later explicit flight.
- `flightCorrelationDescriptor`: `correlation/flight` v1.0.0, readiness `ready`.

## Integration notes (A02/A07)
- Register `flightCorrelator`. For per-branch reports, run `correlateFlights(snapshot.events)`. Group by `target`, and use `registry.flights` for time spans and aliases: `startedAt` and `stoppedAt` for explicit flights, `firstSeenAt` and `lastSeenAt` otherwise.
- `dx mark start` should emit `marker.start` with `context.branch`, `repoCommonDir` and `headSha`. `payload.flightId` is optional.
