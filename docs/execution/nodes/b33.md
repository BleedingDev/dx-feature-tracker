# B33 handoff: strict AI line survival (provenance metric)

Status: **disabled** (the code works and has fixture tests, but no producer exists on this host). A disabled handoff does not mean the module functions on real data.

Contract: `dx.contracts.v1`, digest `sha256:b9623bd4bb6a9b20598a6f0186930153fdf4be77ff40545e03b8e0ba153eb090`.

## What exists

- `packages/core/src/dx/metrics/provenance/metric.ts` exports `provenanceMetric: DxMetric`, `provenanceDescriptor` (id `dx.metric.provenance`, readiness `disabled`), `computeProvenance` and the metric definitions.
- `evidence.ts` holds the Schema-decoded payload contracts, which contain line hashes only and no content:
  - `dx.provenance.edit.v1`: `filePath, sequence, actor (ai|human|unknown), beforeLineHashes (null = missing preimage), afterLineHashes, retryOf?, renamedFrom?, formattingOnly?`
  - `dx.provenance.checkpoint.v1`: `checkpoint, filePath, lineHashes`
  - `dx.provenance.source-attributed.v1`: `sourceName, aiLines, totalLines`
- `alignment.ts` provides LCS alignment that also counts the optimal alignments. When more than one alignment exists, the result is ambiguous (repeated identical lines).
- `survival.ts` gives persistent line-instance IDs to each file's ordered edits and projects them to the named checkpoint.

## Semantics

- Strict survival = AI line instances present at the checkpoint / AI line instances introduced. It uses method `observed` and attribution `strong`, and it counts resolved files only.
- The following unresolved states exclude a file, and the reason is listed: `missing-preimage`, `concurrent-edits` (duplicate sequence), `unknown-change` (preimage differs from the projected state), `ambiguous-repeated-lines`, `tool-retry`, `rename`, `formatting`, `missing-checkpoint`. Any unresolved file, malformed event or incomplete coverage makes the result `partial`.
- A human rewrite is counted only when the edit carries `actor: human`. A removal by an unknown actor is never counted as human.
- A zero denominator, no edits or no named checkpoint gives `unavailable` with a reason.
- The source-attributed share is a separate metric (`source-reported`, `provisional`) and is never merged with observed survival. Heuristic similarity is always `unsupported`.
