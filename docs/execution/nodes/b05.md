# B05 — Cursor hooks collector (degraded)

**Status: degraded.** The decoder, spool, handler and collector are built and tested with 11 passing tests. Live Cursor capture was **not** demonstrated because `cursor-agent status` reports "Not logged in" on this host.

## What exists (`packages/core/src/dx/collectors/cursor-hooks/`)
- `handler.ts`: `handleCursorHook(stdin, runtime)` parses the hook JSON, sanitizes it and resolves the local git branch, HEAD, common dir and worktree using `git rev-parse` with a 1.5 s timeout and no network. It writes one spool file atomically (temp file plus rename, mode 0600) and returns the hook stdout (`{}`, `{continue:true}` or `{permission:allow}`). Failures are skipped, never thrown.
- `sanitize.ts`: keeps only non-content fields. Prompt, response, thought, tool output, command text and email are dropped. It keeps sizes, a command hash, the executable name, and raw numeric usage-like keys, bounded to 32.
- `spool.ts`: the atomic writer and a sorted reader with a file-name cursor. The default directory was the old in-repo spool folder under the worktree; hooks now spool to `~/.dft/spool/<worktree>/cursor-hooks`.
- `decode.ts`: maps a spool record to `dx.event.v1` envelopes. The event ID is the contract's sha256 of adapter, upstreamKey and kind. The stop key is `stop:<conv>:<gen>:stop`, so duplicate stop emissions collapse.
- `collector.ts`: exports `cursorHooksCollector` and `cursorHooksDescriptor` (`collector.cursor-hooks`, degraded). A missing spool fails with `SourceUnavailable`, a missing input fails with `InvalidInput`, and rejected or unknown records return `partial` coverage with gaps.
