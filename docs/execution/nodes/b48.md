# B48 handoff: local feedback collector (optional), DEGRADED

Status: **degraded**. The code works and is tested for the compiler, npm and Vite subroutes. IDE diagnostics and IDE terminal are unsupported, and each reports its own gap.

## What it does
`localFeedbackCollector` (`adapterId: local-feedback`, descriptor `collector/local-feedback`) imports explicitly selected captured logs (a file, or the `.log`/`.txt` files in a directory). A small versioned registry (`LOCAL_FEEDBACK_ADAPTERS` in `collector.ts`, types in `registry.ts`) sends each file to the first adapter that recognizes it. Each file becomes one `feedback.local` event. `adapterVersion` looks like `1.0.0+npm-debug-log@1.0.0`, and `payload.subroute` and `payload.adapter` identify the route.

| Subroute | Adapter | Fields | Honesty |
| --- | --- | --- | --- |
| compiler | `tsc-text@1.0.0` | errorCount, warningCount, reportedErrorCount (`Found N errors`), codeCounts, fileCount, first 50 diagnostics | occurredAt null (no timestamp in output) |
| npm-timing | `npm-debug-log@1.0.0` | command verb, exitCode, durationMs (`timing npm`), timers, httpFetchCount/Ms | durationMs null + reason without `--timing`; occurredAt from log file name; argv/URLs not stored |
| vite-hmr | `vite-dev-log@1.0.0` | viteVersion, readyInMs, hmrUpdates (expands `(xN)`), pageReloads, hmrInvalidations, moduleCount | hmrLatencyMs null; occurredAt null (clock has no date) |
| ide-diagnostics / ide-terminal | none | none | gaps `subroute-unsupported:*` on every batch |

Coverage is `partial` whenever something was recognized, because the IDE subroutes are always unsupported. It is `none` otherwise. Unrecognized files add `input-unrecognized`, and a registered subroute with no input adds `subroute-absent:<subroute>`.
