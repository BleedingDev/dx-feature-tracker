# B28 git churn metric: ready

- **Status:** ready. It is tested against canned git output and a live temporary repository.
- **Exports:** `packages/core/src/dx/metrics/git/metric.ts` exports `gitChurnMetric` (`DxMetric`), `gitChurnDescriptor` (`dx.metric.git-churn`, ready, owner B28), `computeGitChurn` and `gitChurnDefinitions`. `summary.ts` exports `summarizeGitChurn` and `BASE_SHA_DEFINITION`.
- **Input:** `git.commit` and `git.diff` events from the B03 `git-history` collector, plus its coverage. The collector payloads are parsed with Effect Schema.
- **Base-SHA definition:** `baseSha = git merge-base(resolved base ref, HEAD)`, as recorded by git-history. The base ref is the explicit `--base` ref if one is given. Otherwise it is the first of origin/HEAD, main, master, origin/main and origin/master that is not the current branch. Each result carries `checkpoint: range:<baseSha>..<headSha>`. The value `unbounded` means no base resolved, and the result is then partial with a `no-base-ref` reason. The value `mixed` means several bases or heads appear in the snapshot.
- **Metrics:** commits, merge-commits, lines-added, lines-deleted and churn-lines cover non-merge numstat. Binary files are excluded from line counts. files-changed counts distinct paths. files-retouched counts paths touched by two or more commits and is an observable rework signal only. Four metrics come from the latest uncommitted worktree snapshot: uncommitted lines added and deleted, uncommitted files and untracked files. All of them use method `observed` and attribution `not-applicable`. Re-collected commits collapse by SHA.
- **Honesty:** if there is no git-history data, every result has value null and state `unavailable` with a reason, never zero. Truncated paths, partial coverage and multi-branch snapshots set the state to `partial` with a reason.
- **Fixtures:** `b28-branch-snapshot` (`test/dx/fixtures/b28/*.txt`, synthetic) and `b28-live-temp-repo` (a real git repo in the OS temp dir, removed afterAll). They are not added to the fixture index.
- **Checks:**
  - `pnpm --filter @rat-stack/core exec vitest run test/dx/b28.test.ts` exits 0 with 6 passed.
  - `oxlint` and `oxfmt --check` on the B28 files exit 0.
  - Core `tsc` has 0 errors in B28 files. Its overall exit is 1 because of `collectors/opencode/collector.ts` and `reports/explain/timeline.ts`, which other owners hold.
- **Gaps:**
  - The integration owner must register the metric.
  - A clean worktree produces no diff event, so the uncommitted metrics are unavailable instead of 0.
  - Merge and binary lines are not counted.
