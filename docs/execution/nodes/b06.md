# B06 handoff: cursor-local-db collector

Status: **ready** (descriptor readiness `degraded`: opt-in input, no billed charge).

## What it does
`cursorLocalDbCollector` (adapterId `cursor-local-db`) takes an explicitly selected SQLite path plus `scratchDir`,
makes a consistent `node:sqlite` `backup()` copy, reads only the copy (read-only), then removes the copy and its
`-wal/-shm/-journal` sidecars. It recognizes three layouts, otherwise fails `UnsupportedSource`:

| Layout | Tables | Events |
| --- | --- | --- |
| `state-vscdb/composer-headers` | ItemTable, cursorDiskKV, composerHeaders | `ai.session`, `ai.usage`, `ai.turn` |
| `state-vscdb/itemtable` (legacy) | ItemTable (`composer.composerData`), cursorDiskKV | same |
| `ai-tracking` | ai_code_hashes, scored_commits | `ai.tool-edit`, `provenance.attestation` |

Honesty: no prompt/response text, titles, commit messages, file paths or summaries are read into payloads
(canary-tested). Context-window numbers live in `payload.contextMeter` with `notSpend: true`. `usageData.costInCents`
is a `metered` ledger, never `charge`. Cursor's 0/0 token counts are emitted as unavailable with a reason.
`ai_code_hashes.requestId` is a tool-call ref and goes to `payload.toolCallRef`, not `identity.requestId`.
Scoping: with `context.worktreePath`/`repoCommonDir` set, only rows that reference that path are kept; with
`context.branch` set, only matching `scored_commits`. Excluded rows are counted in the `scope-excluded` gap.
