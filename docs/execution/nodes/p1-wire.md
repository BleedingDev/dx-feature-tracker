# P1-WIRE handoff: `dft` binary, global store, auto-sync, history/chats/prices wiring

Status: **ready, with gaps listed below**. Checked at 15:03 CEST.

## What changed
- **Binary `dft`**: `apps/cli/package.json` bin now lists `dft` (`bin/dft` → `dist/dft-main.js`) next to `rat-stack`, and `rat-stack` still works. The verbs are `install`, `status`, `analyze`, `analyse`, `explain`, `history`, `chats`, `mark`, `collect`, `sync`, `evidence`, `hook`, `snapshot` and `mcp` (in `apps/cli/src/dft.ts`). The report verbs take `--since`, `--all-repos`, `--json`, `--no-sync`, `--branch`, `--repo` and `--db`.
- **D7 store**: `resolveDftStore` in `registry/runtime.ts` picks `--db` first, then `$DFT_HOME/dft.db`, then `~/.dft/dft.db`. `dft` always uses that order. The `rat-stack` MCP server and `rat-stack dx` use it too, unless the legacy `DX_STORE` or `DX_REPLAY=1` is set. `--all-repos` clears the repo and branch from the selector.
- **D1 auto-sync** (new `registry/sync.ts`): before running, every report verb and `snapshot` imports the git history of the current worktree, the hook spool (if present), the command log (if present) and every Cursor agent transcript under `~/.cursor/projects/<slug>/agent-transcripts`. The slug is built from the path. It is idempotent: in the scratch run the first sync inserted 4 events and a re-run inserted 0 (4 already stored). A source that fails or is missing is printed on stderr as `unavailable <source>: <reason>`. `--no-sync` skips the sync. `dft sync` runs it alone.
- **Registration**: `makeDxCapabilities` now returns `dx_history` and `dx_chats`, so the CLI, `rat-stack dx history|chats` and the MCP tools all get them. The MCP probe listed 8 dx tools plus inspectFile, printed 0 non-JSON lines and 0 stderr bytes, and a `dx_history` call succeeded. `metricsWithCost(options)` swaps in `makeCostMetric`. `dft` loads `$DFT_HOME/prices.json` if it exists and otherwise uses the bundled `price-table:cursor@2026-09`; if the user file is invalid it prints a warning and falls back. MCP and `rat-stack` use the bundled table. The same cost options go to `dx_history`. `DxCapabilityDeps.selector` (`withSelectorOverrides`) carries `--branch`, `--since` and `--all-repos` into analyze, explain and chats.
- **D4 `dft snapshot`**: runs sync, then analyze (which saves the snapshot manifest in the store), then the history row for the current branch. It appends `{at, branch, headSha, dirty, snapshotId, row, worktree, repoCommonDir}` to `<store dir>/snapshots.jsonl`. It prints one line per money ledger (billed, metered, source estimate, price-table estimate; estimates are labelled, and the ledgers are never summed) plus requests, tokens, agent time and active time. Any failure prints to stderr and still exits 0. `--max-cost N` exits 1 only when a single available ledger is above N; unavailable ledgers are never treated as 0.
- **`dft install`**: merges the 11 Cursor events into the project's `.cursor/hooks.json` with `"<node> <abs>/bin/dft hook"`. Foreign entries and their extra fields are kept, invalid JSON is left untouched, and `~/.cursor` is never written. It also copies `.cursor/skills/*` from the recorder checkout. `--git-hooks` resolves the hooks directory with `git rev-parse --git-path hooks` and appends `<dft> snapshot || true` to `pre-commit` and `pre-push`, creating them if needed. It never replaces an existing hook, and re-running changes nothing. If a `lefthook.yml` exists, it prints a snippet and edits nothing.
- **Skills**: `.cursor/skills/dx-analyze` and `dx-explain` gained a "CLI (preferred)" section (`dft analyze|explain --json`, plus `dft status`, `history`, `chats` and `snapshot`). The MCP routing block is unchanged, and the B40 test passes.

## Gaps
- **Cursor local DB is not auto-synced.** `state.vscdb` is global to all workspaces, and nothing maps its rows to one repo yet. Sync reports it as unavailable with that reason. `dft collect --source cursor-local-db --input <db>` still works explicitly.
- **cursor-cli stream-json captures are not auto-discovered.** No command log records them yet, so use `dft collect --source cursor-cli --input <stream.jsonl>`.
- **The transcript slug is a guess** (non-alphanumeric characters → `-`). Long or temporary paths that Cursor truncates or hashes will not match. When no folder matches, sync reports the transcripts as unavailable.
- **Human output is JSON** for analyze, explain, chats and status, even without `--json`. Only history, snapshot, sync and install have text renderings.
- **`dft collect|mark|evidence`** are `toCommand` projections bound to the default or `DFT_HOME` store. They ignore `--db`.
- **Appended git hooks** do not run if the existing hook ends with `exit` or `exec`. The pre-commit snapshot records the HEAD before the commit.
- **`dft` is not on PATH** unless someone links it (for example with `pnpm link`). Installed hooks call the absolute node and bin path instead.
