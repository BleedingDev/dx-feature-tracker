## Verified against B01

- **Replay twice:** replaying into the same store after a restart, and into an independent store, gives the same snapshot ID, watermark and events. There are 0 new inserts and no coverage blow-up.
- **Out-of-order arrivals:** a frozen snapshot stays frozen, and a new snapshot of the same window gets a new ID. Snapshots are ordered by event time.
- **Failed attempts:** rejected spool files are kept byte-for-byte. A `StoreBusy` append is atomic and succeeds on retry. A stale manifest is not stored.
- **Crash recovery:** a writer SIGKILLed mid-transaction leaves no rows and no held lock. A crash between append and the spool move re-drains as duplicates only. An orphan `.tmp` file is ignored.

No B01 defects were found. One minor non-blocking note: orphan spool `.tmp` files are never cleaned up.
