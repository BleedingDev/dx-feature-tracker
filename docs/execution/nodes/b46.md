## Double-counting rules
- **Root** checkpoint `token_usage` is emitted only inside `provenance.attestation` as `aggregate-alternative`, with `summedIntoTotals: false`. It never becomes an `ai.usage` event.
- **Session**: one `ai.usage` per (checkpoint, session). Its request key is `source:entire:session:<sid>:turn:<checkpointId>`. Repeated pairs are skipped and reported as a gap.
- **Cumulative**: a session that spans checkpoints counts as delta windows only if `checkpoint_transcript_start` strictly increases. Otherwise only the latest checkpoint is counted, `supersededCheckpoints` is listed, and coverage becomes `partial`. `cumulativeVerified` is always `false`.
- **Transcript** windows (`ai.turn`) count tool calls and messages only inside `[start, nextStart)`. Tokens are never read from transcripts.
- Subagent tokens are kept separate and never added to the parent counts. Cost and `tokens.total` stay unavailable. Attribution and branch allocation are `provisional` (Entire's heuristic).
