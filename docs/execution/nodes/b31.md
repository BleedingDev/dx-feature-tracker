## What exists

`packages/core/src/dx/metrics/cost/`:
- `readings.ts` — Schema-decodes AI event payloads into money readings (charge / metered / list-price-estimate / unallocated, USD only; cents converted) and token readings (per category, model, requests). Dedupes by `requestKey` with `AI_SOURCE_PRECEDENCE`; `selectPreferredSource` keeps one source per ledger and names the rest.
- `price-table.ts` — `PriceTableSchema` (id, version, effectiveFrom, USD per million tokens per category). `priceReading` refuses: unknown model, model not in table, before effective date, missing rate for a present category, total-only tokens.
- `metric.ts` — six separate `MetricResult`s, never summed across ledgers:
  - `dx.cost.charge.usd` (source-reported billed)
  - `dx.cost.metered.usd` (source-reported, not billed; e.g. Cursor local `costInCents`)
  - `dx.cost.list-price-estimate.source.usd` (source's own estimate, method `estimated`)
  - `dx.cost.list-price-estimate.price-table.usd` (method `estimated`, reason carries `method=price-table:<id>@<version>`, numerator/denominator = priced/total readings)
  - `dx.cost.subscription-allocation.usd` (method `derived`, plan amount x usage share in period; basis `requests` or `tokens`)
  - `dx.cost.unallocated.usd`
- Exports: `costDescriptor`, `costMetric`, `makeCostMetric(options)`, `computeCost`, `costByBranch` (per-branch results, `null` = unassigned bucket; allocation denominator = whole snapshot).

Branch-scoped snapshots allocate subscription only when `periodUsageTotal` is given; otherwise unavailable with reason.

## Repair (C05 cost by branch, 2026-09-30)

- `costByBranch` gives each request to exactly one branch. It reuses `assignedBranches` from the ai-usage ledger (now exported), so it joins request keys the same way the ledger does. The only known branch wins. Otherwise the branch of the highest-precedence source wins. If that is still ambiguous, the request goes to the unassigned (`null`) bucket.
- Each money ledger picks its preferred source once for the whole snapshot, then splits those readings by branch. Per-branch charge, metered, list-price estimate and unallocated values now add up to the global value. A branch whose only readings were overridden by a better source shows the ledger as unavailable, and its reason names the alternative source that was not summed.
- The ledgers are still kept separate. Missing data stays unavailable.
- B31 fixture change: `feat/a` metered is now unavailable. The global metered value, 0.3 from usage-csv, sits in the unassigned bucket. Before this fix it was also counted as 2.5 local-db on `feat/a`.
- C05 audit: a new test covers one request reported on two branches and checks that every cost ledger adds up to the global value. C05, B30 and B31 tests pass.
