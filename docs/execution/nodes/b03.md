# B03 git history collector: handoff

Status: **ready**. Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.

## What it does
`gitHistoryCollector` (adapterId `git-history`, descriptor `collector.git-history`) reads a selected repo (`selectedInput`, falling back to `context.worktreePath`). It only reads git data and does not write. It emits:
- `git.commit` for each commit in `merge-base(base, HEAD)..HEAD`, with author/committer dates, parents, files changed, lines added/deleted, binary count and paths (capped at 200). `occurredAt` is the committer date and is marked `source-reported`. `observedAt` is the collection time. The payload marks this with `timeBasis: git-committer-date` and `observationMode: backfill`. This keeps commit time and first-observed time separate.
- `git.diff` for the uncommitted worktree compared with HEAD: numstat plus a count of untracked files. `occurredAt` is null.
- `git.observation` for the oldest local reflog entry of the branch. `branchCreatedAt` is set only when that entry is `branch: Created from X`.
Coverage is `complete` when a base was found and nothing was cut off. It is `partial` when there is no base or the history was truncated (over 2000 commits). It is `none` when the repo has no commits yet. With no repo path, the collector fails with `SourceUnavailable`. Event IDs are sha256(adapterId\0upstreamKey\0kind), so they are the same on every run.
