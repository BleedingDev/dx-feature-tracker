# B02 handoff: git-identity collector

Status: **ready**. Contract `dx.contracts.v1`, digest `sha256:b9623bd4...eb090`.

## What it does
`gitIdentityCollector` (R = never; provides `NodeServices.layer`) takes a local repo path (`selectedInput`, falling back to `context.worktreePath`). It runs read-only git commands with `GIT_OPTIONAL_LOCKS=0` and emits one `git.context` event per observed state. The event carries:
- context: `repoCommonDir` (linked worktrees share it), `worktreePath`, `branch` (null when detached), `headSha`, and `flightId` passed through from the input
- payload: `gitDir`, `isLinkedWorktree`, `detached`, `dirty`/`dirtyEntries`, `baseRef`/`baseSource` (`origin-head|local-default|none`), `baseSha` (merge-base), `onBaseBranch`, `aheadCount`, `branchCreatedAt`/`branchCreatedFrom` (reflog), `firstBranchCommitAt`, `worktreeCount`, `sameBranchWorktrees` and `unavailable[]`
- fieldSemantics: `observed` for measured fields and `derived` for baseSha

When a field is missing it stays null. The reason is recorded in `payload.unavailable` and in `coverage.gaps` (`unavailable:<field>`), and coverage becomes `partial`. The eventId follows the frozen recipe `sha256(adapterId\0upstreamKey\0kind)`, so a repeat collect of the same state is deduplicated.

`gitIdentityCollectorEffect` is the same collector with requirements `ChildProcessSpawner | Crypto`, for compositions that already provide NodeServices.
