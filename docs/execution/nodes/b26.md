# B26 handoff: AI conversation/branch correlation

Status: **ready**. It is a pure core module and fully tested against fixtures. Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.

## Entry points

- The code lives in `packages/core/src/dx/correlation/ai/correlator.ts`.
- `aiCorrelator` is the `DxCorrelator`. It returns one branch `Correlation` per AI claim.
- `correlateAi(events, mappings?)` returns the full result: claims, overlapGroups, alternatives, branches and fractions.
- The descriptor is `aiCorrelationDescriptor` in `descriptor.ts` (`correlation/ai`, ready).
- A02/A07 need to register it.

## Rules implemented

**Claims.** An AI claim is an `ai.request`, `ai.turn` or `ai.usage` event. Its source kind comes from `payload.sourceKind`, or from the adapterId when that is missing.

**Overlap.** Claims are grouped by union-find over two strong keys: the raw `requestId` and the turn key `session:generation|turnId`.
- A group with several members is `collapsed`. The preferred member follows `AI_SOURCE_PRECEDENCE`, and non-estimates beat estimates.
- Aggregate ledgers (`dashboard-json` or `payload.aggregate`) become `alternative` groups and are never counted.
- A claim with no id that falls within 60s of another source's claim is `unresolved` and goes into a separate bucket. It is never summed.

**Branch join.** Each claim gets a branch by the first rule that applies:
1. An aggregate claim stays unassigned.
2. An explicit `session:<id>` mapping gives strong attribution.
3. If the event carries branch, worktree and head, attribution is strong. A branch name alone gives provisional attribution.
4. If the conversation has exactly one branch across its events, attribution is provisional. If it spans several branches, the claim stays unassigned.
5. If the claim falls inside exactly one branch activity window (±5 min), attribution is provisional. Otherwise it stays unassigned.

**Fractions.**
- Units are counted once per overlap cluster.
- Amounts come only from the cluster's preferred member, keyed by `ledger:category|currency`.
- Estimates are kept under `estimated:` keys.
- `allocatedFraction` is null, with a reason, when there are no claims.
