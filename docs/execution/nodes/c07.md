## Findings for other owners (not fixed here)
1. **A04 / git metric (high).** `core-golden-flight` records its commits under adapterId `git` with `{insertions, deletions}`. The real git-history collector and the `dx.git.*` metrics use `git-history` with `{sha, linesAdded, linesDeleted, numstatAvailable}`. As a result, the canonical golden fixture reports commits as unavailable even though it expects `commitCount: 2`.
2. **B01 store (medium).** When two batches carry coverage for the same adapter, snapshot coverage is last-append-wins. Changing the append order produces the **same snapshotId** with different coverage, and therefore different metrics. Either the snapshot identity should include coverage, or the merge should not depend on order.
