## Findings (for owners)

1. **High, A02/A07 (`packages/core/src/dx/registry/runtime.ts` `gitSelectorResolver` + store `selectEvents`)**: `dx analyze --flight feature/c09-live` selects only events whose stored `flight_id` equals that string. No collector sets `flight_id`, so only the manual marker is selected and every token/Git metric comes back unavailable or 0 (`run/analyze-flight-flag.json`). Without `--flight` the repo + current-branch selector works. Either map `--flight <branch>` to the branch selector, or have correlation persist flight ids. The smoke script uses the working no-flag path.
2. **Medium (plausible), owner of `dx.flight.tool-calls` (flight-time metric)**: tool calls = 9 with "2 report(s); 0 duplicate report(s) collapsed". cursor-agent reported toolCalls=5 for the turn and the hooks recorded the same turn's tool calls, so the two sources look summed, not deduplicated. Earlier runs: 13 = 7 + 6, 21 in the MCP run.
3. **Low, cursor-hooks collector owner**: its coverage gap `live-capture-not-demonstrated` ("no authenticated cursor-agent session was available") is now false; live capture is demonstrated here. Hook `stop` usage is still `rawUsagePresent=false` in cursor-agent, so tokens come from the stream-json import, not hooks.
4. **Low, C13 / docs**: headless Cursor needs `--approve-mcps` (and `--force` for the call itself to run; without it the call was rejected and the run took 5 min). `cursor-agent mcp list-tools` fails until the server is approved. The installed `.cursor/` files show up as 5 untracked files in `dx.git.untracked-files` for the demo repo.
5. **Info**: the Cursor GUI (IDE) was not driven; the client observation is the `cursor-agent` CLI, which uses the same project hooks and MCP config. Slash-command/skill routing was not tested; the MCP tool was called directly (disclosed fallback).
