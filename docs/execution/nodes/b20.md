# B20 shell-command collector: handoff

Status: **ready** (optional node, tested). Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.

## What exists
- `captureCommand` spawns argv with inherited stdio, appends `start`/`end` JSONL lifecycle records (`dx.shell-command.v1`) with branch/headSha, cwd, exit code, signal or spawn error. `shellExitStatus` returns the status a wrapper should exit with (code, 128+signo, or 127).
- `shellCommandCollector` (adapterId `command-capture`, descriptor `collector/shell-command`) reads an explicitly selected lifecycle log (`selectedInput = <path>`) or shell history (`selectedInput = history:<path>`). It emits `command.run` events, plus `test.result` for recognised test commands (vitest/jest/pytest/cargo test/go test/pnpm|npm|yarn|bun test…), with outcome derived from exit status.
- Event IDs follow the fixture convention `sha256:` + sha256(adapterId NUL upstreamKey NUL kind); evidence hash is over the raw line.
- The cursor is a line offset and stops before any run still missing its end record, so re-collecting is idempotent.
- Argv is redacted: secret-named flags and env vars, token-like values, URL credentials. The canary test proves it.

## Integration notes (A02/A07)
- Register `shellCommandCollector`. It needs `Crypto | FileSystem`; `captureCommand` also needs `ChildProcessSpawner`. `NodeServices.layer` provides all three.
- Suggested surface: `dx run -- <argv>` → `captureCommand({ argv, context, cwd: process cwd, logPath: <store dir>/commands.jsonl })`, then exit with `shellExitStatus(record)`. `dx collect --source command-capture --input <logPath>` ingests the log.
