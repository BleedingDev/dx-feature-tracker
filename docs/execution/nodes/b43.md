# B43 handoff: Cursor dashboard-response import (optional), status DISABLED

Working, fixture-tested collector. It is disabled because no real dashboard response export exists on this host. Producing one needs the logged-in cursor.com dashboard session, and this node must not touch that.

- Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`.
- `packages/core/src/dx/collectors/cursor-dashboard-response/parse.ts`: `parseCursorDashboardResponse(text, options)` decodes the JSON with Effect Schema at the boundary. It accepts one response body, an array of responses, or `{pages:[{request:{page,pageSize},response}]}`. It refuses HAR captures and any file with cookie, authorization or token keys, and the refusal message never echoes the credential value.
  - Per row it records requestId and conversationId (or composerId), model, kind, and the `tokenUsage.*` token counts, but only the ones the row actually has.
  - Cost is `totalCents/100`, or `usageBasedCosts` when that is missing. A cost ledger discriminator says what kind of amount it is, and `charge` is set only for usage-based rows.
  - Rows without a zoned timestamp are rejected.
  - Pagination: `totalUsageEventsCount` is compared with the unique rows. When page and pageSize are known, missing page numbers are listed. Rows repeated across pages are removed. A completeness claim is only made when a total is declared.
- `descriptor.ts`: `cursorDashboardResponseDescriptor` (`collector.cursor-dashboard-response`, readiness `disabled`).
- `collector.ts`: `cursorDashboardResponseCollector`, which reads one explicit `selectedInput` file. It requires FileSystem and Crypto.
- Fixtures (synthetic) in `packages/core/test/dx/fixtures/b43/`: complete-paged, missing-page, single-no-total, har-refused, cookie-refused.
