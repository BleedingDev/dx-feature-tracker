# A02 handoff: v0 CLI/MCP composition

Status: **ready**. The built CLI and stdio MCP serve status, collect, mark, analyze, explain and evidence over a SQLite store for the current Git branch. There is also a `dx hook` Cursor entrypoint. Contract `dx.contracts.v1`, digest `sha256:b9623bd4...b090`.

## Wiring
- `registry/registry.ts`: `allCollectors` (21 modules), `allMetrics` (ai-usage, cost, git-churn, friction, provenance) and `supportDescriptors`. `buildRegistry()` runs A08 `admitDescriptors`. Collect and analyze use only admitted modules; `dx_status` lists everything, disabled modules included.
- `registry/runtime.ts`: `contextForRepo` and `gitSelectorResolver`, which map a repo path to `{repoCommonDir, branch}` for per-branch reports, plus `resolveDxStore`, `dxStoreLayer`, `hookSpoolDirFor` and `runCursorHook`. `composition.ts` re-exports these and adds A07's `autoSources` and `commandLogPath`.
- `capabilities.ts`: `makeDxCapabilities`. It combines the B39 query capabilities with `dx_collect` and `dx_mark`. Collect accepts source aliases (`git-history`, `cursor-hooks`); for `cursor-hooks` it reads `<worktree>/.dx-flight-recorder/cursor-hooks-spool` by default. GitHub errors are mapped to `SourceUnavailable`.
- `apps/cli`: `rat-stack dx <status|collect|mark|analyze|explain|evidence|hook>`. These are toCommand projections of the same capabilities, with the store provided per command. `hook` never opens the store. The MCP `tools` server exposes the six dx tools plus `inspectFile`. Environment: `DX_STORE`, `DX_REPLAY=1`, `DX_REPO`.
