# B36 handoff: explain timeline

Status: ready (core, fixture-tested). Contract `dx.contracts.v1`, digest `sha256:b9623bd4…eb090`; `ExplainTimelineSchema` unchanged.

## What it does
- `buildTimeline(snapshot, {cursor, limit})` (pure): total stable order (known time asc, untimed last, finer precision first, then observedAt, lane, eventId); independent of store order.
- Source lanes = `adapterId` (e.g. `cursor-hooks`, `git-history`, `local-test`); `lanes` sorted.
- `orderingUncertain` when time is missing/unparseable, precision is minute/day/unknown, or another lane shares the same time bucket. Computed over the whole snapshot, so paging never changes flags.
- Pagination: default 50, max 500; cursor bound to the snapshotId, foreign/malformed cursor or bad limit -> `InvalidInput`.
- Summaries: kind + adapter + numeric/boolean payload fields + non-observed methods (e.g. `costUsd:estimated`); never free text. `evidenceIds = [eventId]` (same convention as metrics).
- `explainTimeline(store, request)`: pinned snapshotId reused exactly; unknown -> `SnapshotNotFound`; latest returns actual snapshotId + changed-evidence disclosures (via B35 `selectAnalyzeSnapshot`); adds an untimed-entries disclosure.
