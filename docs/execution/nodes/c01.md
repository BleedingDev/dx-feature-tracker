The audit runs against the frozen A04 core fixtures and the real B01 SQLite store, which it opens in an owned temp dir. It checks three areas:
- **Envelopes:** 30 single-field mutations. The schema rejects unknown, missing or null `schemaVersion`, unknown kind, origin, acquisition or precision, missing blocks, wrong types and a bad value-method. A batch with one bad member is rejected, and so is invalid coverage.
- **Versions:** the fixtures, the manifests and all 5 metric descriptors carry the current version and digest. The store fails closed with `StoreError` on a persisted `dx.event.v2` row.
- **Metrics:** ai-usage, cost, friction, git-churn and provenance each run on the 6 core fixtures. A null value needs a reason and a non-measured state. Unavailable means a null value, a zero denominator means null, and an estimate must use the estimated method. No metric reports a measured value when every source is unavailable. Results are deterministic, and a null value cites its coverage.

## Findings (for owners)
1. **B01 (medium):** `append` does not decode envelopes, so an unknown-version row gets stored. After that, every snapshot over that row fails. It should validate on append.
2. **git-churn and provenance (medium):** every null result has an empty `coverage`. These are allow-listed in `known-findings.json`; remove the entry once fixed.
3. **friction (low):** on `core-secret-canary`, one measured result has empty coverage.
4. **A03 (low):** the schema lets these through: non-ISO timestamps, free-form `eventId`, empty `adapterId`, and unknown fields (silently stripped). The manifest `contractVersion` is free text, and only the store's digest check guards it.
