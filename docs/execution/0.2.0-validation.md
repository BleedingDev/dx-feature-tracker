# 0.2.0 validation

Evidence that dft 0.2.0 reads all seven tools correctly on real sessions, run on 2026-10-01 on the maintainer's machine (macOS, Node 26.10.0). Every number below was produced by the built CLI against a throwaway `DFT_HOME`; the tools' own folders (`~/.claude`, `~/.codex`, `~/.local/share/opencode`, `~/.pi`, `~/.omp`, `~/.dsh`) were only read. Paths are shown relative to the scratch folder `realdata/`.

Each `manifest.json` holds totals computed independently of dft from the raw session files (its `tokenRule` says how).

## Commands

```sh
pnpm build
export DFT_HOME=<scratch>/e2e/dft-home DFT_CURSOR_USAGE=off
# Pi's realdata sessions were written with --session-dir:
export PI_CODING_AGENT_SESSION_DIR=realdata/pi/pi-sessions

# in every repo and worktree above
dft install                     # project-local capture only, no --telemetry
dft sync --verbose
dft usage --by branch --repo . --json --metric input,cacheRead,cacheWrite,output,reasoning,requests,estimate,toolFigure,tokens
dft usage --by session --tool <tool> --json --metric ...
dft analyze --json; dft history --json; dft chats --json

# across every repo
dft usage --by tool | --by model | --by branch | --by provider | --by via
dft history --all-repos --since 365d [--group-by tool]
dft chats --all-repos
dft status
```

The comparison scripts (`compare.py`, `matrix.py`, `split.py`, `consistency.py`, `estimate.py`) stayed in the session scratchpad; they parse each manifest's own field names and call the CLI with `--json --no-sync`.

## Estimates

- **Claude Code:** dft's estimate equals the `total_cost_usd` that `claude -p` printed for every run (the manifest's `resultCostUsd`), to the last digit: 0.1857392, 0.2336492 (three resumed turns), 0.1805054, 0.2454612 (parent 0.1283732 + subagent 0.117088) and 0.413175 (0.2496682 + 0.1635068).
- **Codex, DeepSeek Harness, Pi:** recomputed from the manifests' buckets times the models.dev 2026-10-01 prices (`estimate.py`): all 16 sessions equal dft's estimate within 1e-17.
- **OMP:** dft's estimate equals OMP's own stored cost for 9 of 10 sessions. `01a0f780-692d` used `factory/glm-5.3-flash` through cliproxy for part of the session; dft prices it at the maker's price (D30), OMP at the gateway's.
- **OpenCode:** dft's estimate is 0.00006 below OpenCode's stored cost in every session. The gap is the per-session overhead row (title and compaction calls OpenCode adds to the session total without a message or model): dft keeps its tokens but cannot price it, and reports those 5 requests as unpriced (`dft chats` and `coverage.unpriced`).

## Live capture

`dft dashboard --no-open --port 7431` ran while one fresh cheap session per tool ran in a new branch of its scratch repo (`live.py`: `claude -p --model sonnet`, `codex exec -m gpt-5.6-luna`, `opencode run -m opencode-go/gpt-5.6-luna`, `pi -p --model cliproxy/gpt-5.6-luna`, `omp -p --provider cliproxy --model gpt-5.6-luna`, `dsh headless` with the router overlay and `.dsh/dft.patch.yml`). The poller read the store every 0.5 s after the tool exited.

| Tool | Branch | Run | Session file in store | Hooks or extension in store | Branch source |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `feat/claude-code-live` | 10.6 s | 0 s | 0 s (hooks) | `harness-recorded`, hooks `hook` |
| Codex | `feat/codex-live` | 7.9 s | 0 s (turn at 5 s) | none: project hooks need trust and approval | `session-recorded` |

| Pi | `feat/pi-live` | 1.8 s | 1 s | none: `.pi/extensions` needs folder trust | `cwd-inferred` |
| Pi with `-e .pi/extensions/dft-observer.ts` | `feat/pi-ext-live` | 1.5 s | 4 s | 4 s (extension) | `cwd-inferred`, extension `hook` |
| OMP | `feat/omp-live` | 3.9 s | 8.6 s | none: `omp -p` did not load `.omp/extensions` | `cwd-inferred` |

| DeepSeek Harness | `feat/deepseek-live` | 3.5 s | 8.6 s | 8.6 s (hook bridge) | `cwd-inferred`, bridge `hook` |

Before this release only hook notes, git changes and a 60 s poll triggered a dashboard sync, so the four tools without loaded hooks waited up to a minute. The session-folder watch fixed that. The first OpenCode attempt was recorded under the poller's own folder because `opencode run` takes its folder from `PWD`, not the process folder; the rerun set `PWD`. Afterwards `dft uninstall` removed every capture file from all 12 repos and worktrees and left each `git status` clean.
