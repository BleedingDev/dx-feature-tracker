# 0.2.0 validation

Evidence that dft 0.2.0 reads all seven tools correctly on real sessions, run on 2026-10-01 on the maintainer's machine (macOS, Node 26.10.0). Every number below was produced by the built CLI against a throwaway `DFT_HOME`; the tools' own folders (`~/.claude`, `~/.codex`, `~/.local/share/opencode`, `~/.pi`, `~/.omp`, `~/.dsh`) were only read. Paths are shown relative to the scratch folder `realdata/`. The final check of the packed release tarball, installed as a new user would install it, is in [Release candidate](#release-candidate).

| DeepSeek Harness | 0.2.0-rc.2 | `realdata/deepseek/{repo,wt-two,norepo}`, 6 manifest sessions |

Each `manifest.json` holds totals computed independently of dft from the raw session files (its `tokenRule` says how).

## Commands

```sh
pnpm build
export DFT_HOME=<scratch>/e2e/dft-home DFT_CURSOR_USAGE=off
# Pi's realdata sessions were written with --session-dir:
export PI_CODING_AGENT_SESSION_DIR=realdata/pi/pi-sessions

# in every repo and worktree above
dft install                     # project-local capture only, no --telemetry
dft sync --verbose
dft usage --by branch --repo . --json --metric input,cacheRead,cacheWrite,output,reasoning,requests,estimate,toolFigure,tokens
dft usage --by session --tool <tool> --json --metric ...
dft analyze --json; dft history --json; dft chats --json

# across every repo
dft usage --by tool | --by model | --by branch | --by provider | --by via
dft history --all-repos --since 365d [--group-by tool]
dft chats --all-repos
dft status
```

The comparison scripts (`compare.py`, `matrix.py`, `split.py`, `consistency.py`, `estimate.py`) stayed in the session scratchpad; they parse each manifest's own field names and call the CLI with `--json --no-sync`.

## Estimates

- **Claude Code:** dft's estimate equals the `total_cost_usd` that `claude -p` printed for every run (the manifest's `resultCostUsd`), to the last digit: 0.1857392, 0.2336492 (three resumed turns), 0.1805054, 0.2454612 (parent 0.1283732 + subagent 0.117088) and 0.413175 (0.2496682 + 0.1635068).
- **Codex, DeepSeek Harness, Pi:** recomputed from the manifests' buckets times the models.dev 2026-10-01 prices (`estimate.py`): all 16 sessions equal dft's estimate within 1e-17.
- **OMP:** dft's estimate equals OMP's own stored cost for 9 of 10 sessions. `01a0f780-692d` used `factory/glm-5.3-flash` through cliproxy for part of the session; dft prices it at the maker's price (D30), OMP at the gateway's.
- **OpenCode:** dft's estimate is 0.00006 below OpenCode's stored cost in every session. The gap is the per-session overhead row (title and compaction calls OpenCode adds to the session total without a message or model): dft keeps its tokens but cannot price it, and reports those 5 requests as unpriced (`dft chats` and `coverage.unpriced`).

## Release candidate

On 2026-10-01 the release tarball was built from `3a39b2f` with the version set to 0.2.0, which is what the `release: v0.2.0` commit ships, and checked the way a new user gets it. The install and every command ran with Node 24.18.0, the oldest supported version.

### Package

- `PNPM_BIN=~/.proto/tools/pnpm/11.3.0/shims/pnpm sh packages/dft-npm/scripts/bundle.sh`, then `npm pack`: `dx-feature-tracker-0.2.0.tgz`, 2 677 557 bytes, 15 files, sha256 `4c20ed06ff3830356f3879d4ad8a43f28c8c3aea404cab4683fa8f28474aac91`. A second bundle and pack gave the same sha256.
- It holds every file `scripts/release.sh` checks for (`package.json` at 0.2.0, `dist/dft.mjs`, `dist/dft-main.mjs`, `dist/check-node.cjs`, the intro video and poster) and the six Cursor skills.
- No file in `dist` or in the unpacked tarball contains the builder's home path. `dist/dft.mjs --version` prints `dft v0.2.0` and `node dist/check-node.cjs` exits 0.

### New user

`npm install -g` of the tarball into an empty npm prefix, with a new `HOME` that holds copies of the scratch sessions only: the `realdata` Claude Code project folders and the parent `-private-tmp` folder, the 15 Codex rollouts that name `realdata/codex`, a backup of the OpenCode database, Pi's `pi-sessions` (found through Pi's own `settings.json` `sessionDir`, no environment variable) and its live-run folder, and the OMP and DeepSeek Harness folders of the scratch repos. No `DFT_HOME` was set, so the store was the new user's `~/.dft`. There is no Cursor login in that `HOME`, and every command says "Cursor account: unavailable: not logged in".

| Step | Result |
| --- | --- |
| `dft --version` | `dft v0.2.0` |
| `dft install` in a clone of `realdata/claude-code/repo` | Cursor hooks and the six skills, Claude Code and Codex hooks, the OpenCode plugin, the Pi and OMP extensions, and the DeepSeek Harness hooks and patch, each with its trust or start note. Hook commands name the absolute Node and `dft` paths. All 14 files are listed in `.git/info/exclude`, so `git status` stays empty. |
| `dft uninstall` in the same clone | removes all 14 files and the exclude lines; `git status --ignored` is empty |
| `dft sync --verbose` in all 18 repos, worktrees and outside-repo folders of `realdata` | exit 0 everywhere, no `git status` changed and no file under `.git` changed |
| `dft status` outside a repo | `Branch: none, this folder is not a git repo` (it said `detached HEAD` before `776461e`) |
| `dft status`, `dft usage --by tool`, `model`, `branch`, `repo`, `provider` and `via`, `dft history`, `dft history --all-repos --since 365d` (also `--group-by tool`), `dft chats`, `dft chats --all-repos`, `dft analyze`, `dft line` | exit 0, each within 4 s including its sync |
| `dft dashboard --one-time --no-open`, also `--all-repos` | saved to `~/.dft/dashboard.html` (or `--out`); the page loads nothing from the internet and leaves chat titles out |
| `dx_usage` through `dft mcp` (stdio, `groupBy: tool`) | the same per-tool numbers as the CLI; nothing on stderr |

The CLI, the saved dashboard and MCP agree on the totals: $3.23 estimate, $2.93 tool's figure, 6.2M tokens, 244 requests and 6 unpriced requests (OpenCode's per-session overhead rows). `dft usage --metric sessions` counts 61 sessions. Rerun through the installed CLI, the comparison scripts give the same results as the sections above: 38 of 38 manifest sessions match every recorded bucket, all 38 estimates equal the tables, every single-branch session lands on its branch, the six branch-switch splits equal the `split.py` counts, and `dft history` agrees with `dft usage --by branch` on all 32 branches.

A session figure of a chat that ran on two branches stays whole and shows under `(unattributed)` in `dft usage --by branch`, as [usage.md](../architecture/usage.md) describes: Claude Code's `1100de81` puts $0.23 of tool's figure there, with no tokens, while `--by repo` keeps it under `claude-code/repo`.

### Old Node

`dft --version` under Node 18.20.8, 20.20.2 and 22.23.3 prints the "dft needs Node.js 24.18.0 or newer" box with upgrade steps and exits 1; Node 24.18.0, 25.9.0 and 26.10.0 print `dft v0.2.0`. `npm install -g` under Node 22.23.3 installs with an `EBADENGINE` warning, because npm does not block on `engines`, and the first `dft install` then prints the same box.
